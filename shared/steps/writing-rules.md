# Writing rules worth remembering

<!-- Shared by the plan, prototype, from-app, from-app-update and update skills. -->

- **Titles** name an outcome or a capability ("Recipe collection"), never an activity ("Build recipe module").
- **Reference instead of copying.** Cite sources by section (`SRC-2 §3.1`), and cite NFRs by ID.
- **Priorities.** Use the ones the source states. When it states none, propose them from the phases, milestones and goals (by default the first release Must, later ones Should), mark each one "(proposed)", and list them in the G3 message for confirmation.
- **Phases and milestones** are never Epics. Check with the test: does it reach done by doing work (an item), or is it a point where you check something is true (a milestone)?
- **Delivery-level names never label an Epic or Feature.** In the output, do not call them "User Story", "PBI", "Requirement" or "Issue".
- **Questions to the user use everyday words.** Avoid planner terms ("priority", "deferred need", "milestone", "traces to"), or explain them in the same sentence, and say what each answer changes: "Should the first release include exporting the lending history? If no, no work item is created for it now." Each question also carries its proposed answer.
- **Claude proposes; the user decides.** Never mark a gate as passed on the user's behalf.
